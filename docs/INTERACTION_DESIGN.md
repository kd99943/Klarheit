# Klarheit 选框、试戴与购镜交互改进

## 第一版先改哪里

**先做商品详情与试戴之间的往返。** 用户选一个颜色，立即看到这个颜色的实拍或标明来源的 3D 预览。进入试戴、拒绝摄像头或返回详情时，选择仍在。点击加购后，当场看到加入了哪一副，可以撤销、继续选或自己去购物车。这段路径是新用户最早能感受到 Klarheit 有何不同的地方，完成它也容易用手机验证。

当前版本已经有款色交接、处方示例、镜片选择、继续支付、履约状态和售后工单。新的设计重点是让这些能力在用户需要它们的时候出现。首轮可以用四个问题检查每次操作：选中了什么、发生了什么、能否反悔、下一步做什么。

## 2. 首轮交互稿

以下文案用银色镜架举例。上线时使用真实商品名称、对应资产和可售状态。

### 商品详情｜选择就有结果

1. 在图片区旁边显示当前选择「AERO X1 · 银色」，色卡同时有色样、颜色名和选中状态。点选颜色后更新主图。如果该色有不同角度实拍，可以左右滑动，或点按「正面」「侧面」。
2. 没有该色实拍时，在图片区显示「银色暂无对应实拍」和可用的下一步。有相应模型时可点「看银色 3D 预览」。通用图片继续显示时标明「款式示意图」。库存按已有数据的实际粒度展示，只有商品级库存时用「该款可购」。
3. 手机底部显示当前款色和主动作「选镜片」，旁边保留「试戴这款」。选色处也显示微缩预览或已更新的颜色名，用户无需上滑才能确认变化。
4. 已确定款色时，在详情、试戴、配镜及返回路径使用同一商品与款色标识。款色失效时保留可继续用的选择，提示「这款颜色暂不可选，请选择其他颜色」。用户做出新选择后再继续。

**验收**：从目录点进商品，切换到第二个颜色。其名称、选中态和视觉区域有明确变化。没有专属图片时有清楚标识。进入试戴再返回，仍显示第二个颜色。用两款都有「银色」的商品确认不会串款。

### 试戴｜先看这副，再决定开相机

| 用户所处状态 | 页面反馈与当前操作 |
| --- | --- |
| 刚进入 | 标题显示「试戴 AERO X1 · 银色」，先放当前款色的静态图或 3D。主按钮「开启摄像头」，次按钮「先看模型」。启动前用一句话解释相机用途。 |
| 正在等相机 | 显示「正在等待摄像头权限」。用户关闭或拒绝系统弹窗后，可以回到选框或选择「先看模型」。 |
| 已开启，尚未跟踪 | 屏幕只保留当前最有用的一条指导，比如「把脸移到框内」。提示相同且持续时保持稳定，避免频繁闪动。 |
| 拒绝或不可用 | 保留同款同色，显示「摄像头未开启，你仍可看模型或继续配镜」。有重试条件时提供「重试相机」，一直保留「继续配镜」。 |
| 正在试戴 | 颜色和镜框切换后有名称反馈。拍照与下载沿用现有操作。离开页面关闭相机，退出前可以直接保存当前商品选择。 |

**验收**：手机上点进试戴时能先识别当前镜框。拒绝权限后仍能继续看同款或进入配镜。成功开启后切换颜色，再从试戴返回详情。检查带回的仍是用户最后确认的款色。

第二轮可做一项有辨识度的互动：**同一张脸对比两副眼镜**。让用户从浏览和试戴中自选 A、B，保持同一个相机视图，用「看 A」「看 B」切换。无摄像头时试用同角度的实拍或 3D，补上真实尺码和镜架价。手机优先快速切换，桌面再考虑并排。首版对比无需持久保存试戴图。 [现有对比组件](../front_end/src/ar/FrameCompare.tsx) · [现有 3D 展示](../front_end/src/ar/FrameShowcase.tsx)

### 加购和回目录｜保留原来的位置

- 点击加购后留在原页，确认条显示「已加入 AERO X1 · 银色」，若还没选镜片则补「待配镜」。提供「查看购物车」「撤销」。用户继续滑动、选色或看模型时不会被弹层挡住。
- 撤销只移除刚加入的那条配置，购物车数量同步。快速连点防止重复添加。再次明确添加同款时，按实际购物车逻辑展示新增项或已有项状态。
- 详情页返回时恢复目录的关键词、筛选、排序和原列表位置。手机筛选入口显示「筛选（2）」和当前结果数。已选条件可单独移除，无结果时给「移除一个筛选条件」。
- **验收**：设置两个筛选，进入结果列表靠后的商品，选色、加购、撤销、返回列表。筛选和原商品位置恢复。购物车里的其他配置都能继续使用。

## 3. 第二轮把反馈延伸到成交和售后

| 改动 | 交互描述 | 验收 |
| --- | --- | --- |
| 配镜显示实时配置 | 手机底栏放「银色 · 预计 ¥…」与当前步骤动作。变更镜片后显示有依据的价差与合计。处方按左右眼组织，字段旁可打开现有示例并高亮对应位置。表单不通过时定位第一个错误。 | 改镜片、返回上一步、修改镀膜时，用户能复述镜框、当前选择和预计合计。虚拟键盘弹出时底栏不挡输入。 |
| 从两条路径进入结账 | 进入结账前明确显示当前佩戴人和是否保存处方。经购物车时恢复账号内确认过的选项，或在结账重新确认。继续草稿时明确写出已恢复的内容，例如「已保留镜框和颜色，处方请重新确认」。 | 分别完成「直接结账」和「先加入购物车」。佩戴人一致或有明确的复核步骤，保存处方始终由用户决定。草稿恢复使用账号范围内的数据。 |
| 购物车选中项可读 | 每个条目用清楚的「本次结算」单选。底部说明「本次结算 1 副，其他配置保留」，标出款色、当前金额和「继续配镜」或「结算此副」。删项给撤销。 | 车里有两副，一副未配。用户能不靠猜测选中目标条目，完成以后另一副还在。 |
| 结账失败可修正 | 把完成度数字转成能点到对应区块的状态，例如「还差收货地址」「重新确认金额」。提交后显示实际处理阶段。订单状态查询失败时显示「暂时无法确认 · 重新查询」，原单号仍可见。只有确认可以付款时才显示「继续支付」。 | 模拟金额更新、弱网提交和支付回跳失败，用户能回到下一个有效步骤，页面不会用默认零元或未支付代表未知结果。 |
| 订单首屏随状态变化 | 待补资料时显示「补充配镜资料」，直达现有工单的相关类型。已有工单优先给「查看处理进度」。已发货提供「复制运单号」，有有效查件链接再提供「查看物流」。记录加载失败显示「暂时无法加载售后记录 · 重试」。 | 待付款、待补资料、已发货、存在售后单四种状态各走一次。用户能用一次点击到正确动作，售后接口失败时仍可看订单。 |

首轮无需先做附件系统。补资料动作可先复用现有类型与客服分派。页面说明工作人员会确认所需资料和提交方式，通用售后备注只收处理所需的信息。 [处方与镜片选择](../front_end/src/pages/ConfigLab.tsx) · [结账](../front_end/src/pages/Checkout.tsx) · [支付确认](../front_end/src/pages/OrderConfirmationPage.tsx) · [售后](../front_end/src/pages/OrderDetailPage.tsx)

## 4. 用真实任务验收交互

| 优先级 | 交付目标 | 验收记录 |
| --- | --- | --- |
| 第一轮 | 款色即时反馈、相机由用户开启、拒绝后继续、加购原位确认、返回目录恢复。 | 邀请目标用户用自己的手机找一款、换色、拒绝相机后继续试戴或配镜、加购、撤销并返回列表。记录独立完成的人数、第一次卡住的位置和出现重复选择的步骤。 |
| 第二轮 | 用户自选两款对比、配镜价格及结算反馈、订单首屏动作。 | 让用户说出对比的是哪两款、当前预计费用和这一单需要做什么。再走弱网回跳、查件和补资料场景，观察他们是否能找到正确动作。 |
| 后续按反馈 | 尺码辅助筛选、未登录镜片估价、已确认的配镜草稿。 | 观察真实用户是否经常不知道如何挑尺码、担心加价或返回后从头填。按最常见的失败原因安排。 |

同一组任务覆盖窄屏与桌面、简体中文与英文，以及键盘和屏幕阅读器。颜色、价格和状态变化都有可读文本。动效集中在选中、价格更新、确认和撤销，开启系统的减少动态效果时保留完整信息。试运行可记录「点选颜色后进入试戴或配镜的比例」「试戴失败后继续选框的比例」「选框到加购的返回次数」，结合观察找改动前后的差别。

本次核对以当前工作区为准。用本地测试商品在 Chrome 的 390 像素视口复核了色卡切换时主图保持原样、加购后跳转购物车，以及拒绝相机后仍可查看模型与继续配镜。登录后的配置、支付与售后流程基于源码评审，方案中的真机与用户任务用于下一轮验收。

## 5. 第一轮实施落地记录

以下第一轮核心交互已在当前工作区完成实现与本地单测验证：

- **商品详情｜选择就有结果**：统一默认款色解析与按商品 ID 隔离的 `(productId, finishId)` 状态回传（`front_end/src/lib/selection.ts`），支持 `?finish=` 与路由状态往返恢复、失效款色拦截提示、多角度实拍切换/滑动、无专属实拍时的「款式示意图」标明与按需懒加载 3D 真色预览（`FrameShowcase` 支持拖拽旋转与系统减少动效），以及移动端底部固定栏。
- **试戴｜先看这副，再决定开相机**：移除页面挂载自动请求摄像头，改为先展示当前款色预览、隐私一句话与「开启摄像头 / 先看模型 / 继续配镜」明确操作；等待权限、拒绝/不可用与实时试戴状态均保留同款同色并支持带回最后选中的款色返回商品详情；中英文校准引导去重防抖。
- **加购原位确认撤销 & 回目录恢复**：`useCart.addItem()` 返回新增条目并防 600ms 连点重复，详情页与试戴页加购后原位提示并支持单条精确撤销；目录页筛选与排序同步到 URL 查询参数，移动端收起为带计数的「筛选（N）」面板，提供单个已选条件芯片移除、无结果「移除一个筛选条件」，以及返回目录时恢复筛选与原商品位置高亮。

## 6. 第二轮实施落地记录

以下第二轮成交、对比与售后交互改进也已在当前工作区完成实现与本地单测验证：

- **同一张脸自选 A/B 对比**：升级 [FrameCompare.tsx](../front_end/src/ar/FrameCompare.tsx) 与 [ARVirtualStudio.tsx](../front_end/src/pages/ARVirtualStudio.tsx)，支持用户在实时摄像头视图下保持同一画面点击「看 A」「看 B」即时换镜对比，并在无相机/模型模式下提供自选 A/B 框型与色款、真实尺码与镜架价对照（移动端单画布快速切换防 WebGL 过载，桌面端可选并排视图），并彻底移除旧组件中残留的硬编码中文。
- **配镜实时反馈与双路径一致**：[ConfigLab.tsx](../front_end/src/pages/ConfigLab.tsx) 将处方按右眼 (OD) / 左眼 (OS) / 瞳距 (PD) 分组，字段旁可一键打开并高亮对应示例片段；表单校验失败自动定位并聚焦首个错误字段；切换镜片实时显示价差与预计合计；手机端新增底栏实时回显款色与预计金额，且输入框获焦时自动隐藏避免与虚拟键盘冲突；佩戴人与「是否保存处方」同步写入购物车与直连结账两条路径。
- **购物车清晰单选与删项撤销**：[CartPage.tsx](../front_end/src/pages/CartPage.tsx) 与 [useCart.tsx](../front_end/src/hooks/useCart.tsx) 为每条配置增加「本次结算」显式单选、中文/英文色名本地化、佩戴人/保存处方标识、底部「本次结算 1 副，其他配置保留」提示及删除后原位撤销恢复。
- **结账可修正状态与未知状态不误导**：[Checkout.tsx](../front_end/src/pages/Checkout.tsx) 将完成度数字升级为可点击跳转至对应区块的待办状态条，按账号范围恢复草稿并明确告知已保留内容，增加价格变动显式勾选确认、处方保存复核及真实提交阶段文案；[OrderConfirmationPage.tsx](../front_end/src/pages/OrderConfirmationPage.tsx) 在查单失败时保留原单号并显示「暂时无法确认订单状态 · 重新查询」，不再以零元或未支付代替未知状态。
- **订单首屏主动作与售后容错**：[OrderDetailPage.tsx](../front_end/src/pages/OrderDetailPage.tsx) 首屏按优先级突出唯一当前最需处理的动作（状态未知重查 → 待支付续付/刷新 → 已有处理中工单直达进度 → 待补资料直达补充工单并说明无附件流转口径 → 已发货一键复制运单号与受控物流查件链接）；售后记录接口独立加载，失败时仍可正常查看订单并提供「暂时无法加载售后记录 · 重试」。
