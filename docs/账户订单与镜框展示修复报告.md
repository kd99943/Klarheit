# Klarheit 账户、订单与镜框展示修复报告

本报告依据当前工作区源码编写，供手动实施。以下验收项均待改动后执行。建议先拆订单页，再验证账户布局，因为移出订单列表会改变页面高度。3D 控件和商品目录可以分别实施。

## 一、让“我的订单”进入独立页面

**定位。** 在 `front_end/src/components/layout/Navbar.tsx` 中，账户菜单的两个按钮都执行 `navigate("/my-account")`。“我的订单”按钮右侧还重复显示“我的账户”。`front_end/src/App.tsx` 已有单笔订单详情路由 `/order/:orderNumber`，订单列表则直接写在 `MyAccountPage.tsx` 中。现有 `useOrders()` 已能读取当前用户的订单，拆页可以复用它。

| 入口 | 建议目标 | 页面内容 |
| --- | --- | --- |
| 我的账户 | `/my-account` | 账户概览、资料、地址、安全信息，以及“查看我的订单”链接 |
| 我的订单 | `/my-orders` | 当前用户的订单列表、订单状态和金额 |
| 点击某笔订单 | `/order/:orderNumber` | 该订单的详情和后续操作 |

1. 在 `front_end/src/pages/` 新增 `MyOrdersPage.tsx`。从 `MyAccountPage.tsx` 移入订单列表、加载中、加载失败、空列表四种显示状态，以及支付返回提示。连同 `useOrders()`、`orders_list_viewed` 和按订单号调用的 `completeOrderCartCleanup` 一并迁移，保留原有清理条件。账户页保留 `account_page_viewed`，把原列表换成一个订单入口。同步调整中英文标题和账户页简介。
2. 在 `App.tsx` 按账户页现有模式懒加载新页面，并用 `ProtectedRoute` 包裹 `path="my-orders"`。在 `auth/AuthProvider.tsx` 的受保护路径判断以及退出登录后的跳转判断中补入新路径。
3. 在 `Navbar.tsx` 分别连接两个按钮，去掉订单按钮右侧误导性的账户标签。移动端已登录菜单也添加“我的订单”。在 `OrderConfirmationPage.tsx` 修改“查看我的订单”的目标。在 `OrderDetailPage.tsx` 将普通用户的返回目标及两处按钮文案改为“返回我的订单”，管理员查看订单时仍返回 `/admin`。
4. **兼容支付返回。** 当前支付宝默认同步返回地址由 `PaymentServiceImpl.resolveReturnUrl()` 生成，模拟支付页在 `MockPaymentController.java` 中也有返回账户页的路径。可以先发布支持新旧地址的前端：若旧地址 `/my-account` 带有 `out_trade_no` 或 `orderNumber`，使用 `<Navigate to={{ pathname: "/my-orders", search: location.search }} replace />` 转交；普通账户访问照常展示。随后调整后端默认返回地址、模拟支付返回地址及已显式配置的 `ALIPAY_RETURN_URL`。返回提示使用查询参数定位订单，实际支付状态取自服务端。此次改动只涉及浏览器同步返回地址。
5. 更新 `CheckoutFlow.test.tsx` 中明确期待“我的订单”进入 `/my-account` 的旧用例。给两个按钮设置不同的测试目的地，分别点击并断言。若修改后端默认返回地址，同时更新 `PaymentServiceImplTest.java` 中对应的断言。

**验收。** 在桌面和手机宽度下各点击两个入口，核对地址栏和页面标题。用空订单账户验证空状态，用有订单的账户执行“列表 → 详情 → 返回列表”。退出登录后直接访问新路由应要求登录。再以已有测试订单访问旧支付返回链接，确认订单号保留、状态可查，购物车清理只影响该订单关联的商品。

## 二、让“账户操作”和“安全与隐私”一起滚动

**定位。** 在 `MyAccountPage.tsx` 右侧栏，上方 `quickActions` 卡片单独带有 `xl:sticky xl:top-28`，下方 `compliance` 卡片处于普通文档流。宽屏滚动时，上卡会停靠在视口中，下卡会继续向它靠近。页面左侧还有一个同名的“安全与隐私”区块，修改位置应以右侧的 `quickActions` 和 `compliance` 为准。

**改法。** 删除上方 `SectionCard` 的 `className="xl:sticky xl:top-28"`，保留父容器 `flex flex-col gap-6`。这样两张卡沿同一文档流滚动，卡片高度也可以随文本换行自然增长。`ProfileDetailsPage.tsx` 的 `sidebar.actions` 与下方 `sidebar.security` 使用了相同布局，可在资料页一并移除上卡的这两个类。

**验收。** 先以 1440 × 768 打开账户页，从页首缓慢滚到页尾再滚回。上卡底边与下卡顶边应始终留有间距，卡片内链接均可点击。拆页后若页面过短，可降低浏览器窗口高度以触发滚动。再以 390px 宽度验证单列显示，并在资料页重复一次。

## 三、让镜框能翻到顶面、底面和背面

**定位。** `front_end/src/ar/FrameShowcase.tsx` 的 `onPointerMove` 只读取横向位移，还把 Y 轴角度限制在 ±1.1 弧度（约 ±63°）。同时，动画循环 `tick()` 每帧执行 `showcase.rotation.x = 0.1`。只移除水平限幅，或只添加纵向拖拽，都会留下一个方向受限。

**改法。** 继续旋转现有的 `showcase` 容器。模型已按包围盒居中，相机也会按包围球和视口比例取景，无需更换渲染器或重新制作原有模型。

1. 在首次绘制前设置初始俯角。按下时记录活动指针的 `pointerId`、起点 `clientX/clientY` 和当时的 X、Y 角度。沿用当前灵敏度时，移动中的核心计算如下，两个角度都允许连续累加。

   ```ts
   showcase.rotation.y = startYaw + (event.clientX - startX) * 0.008;
   showcase.rotation.x = startPitch + (event.clientY - startY) * 0.008;
   ```

2. 把自动摆动限制到用户首次操作之前；删除 `tick()` 对 X 轴的逐帧赋值。松手后保持当前姿态，再次按下以该姿态为起点。保留现有“减少动态效果”偏好和页面隐藏时暂停绘制的行为。
3. 在交互画布上把 `touchAction` 从 `pan-y` 改为 `none`，让纵向手势也传给模型。用 `setPointerCapture` 持续接收拖出画布的手势，只处理活动指针，并在 `pointerup`、`pointercancel` 或失去捕获时结束拖动。画布外保持正常页面滑动。把中英文 `ar-studio.json` 的 `modelMode.dragHint` 更新为“上下左右拖动，可查看镜框各个角度”及对应英文。

**验收。** 分别从商品详情的 3D 预览和虚拟试戴工作室的模型展示进入。横拖直到看到镜腿后端，再沿同一方向转回正面；竖拖依次看到顶部、底部并翻回；斜拖后松手并再次拖动，姿态应连续。手机单指竖拖时模型跟手，手指从画布外起滑时页面仍可滚动。在 `FrameShowcase.test.tsx` 增加一次横向超过旧限幅、一次纵向拖动以及松手后下一帧保持角度的断言。

## 四、扩充眼镜样品，让不同款式一眼可辨

**定位。** 项目内置目录由 Flyway 的 `V8__seed_catalog_data_and_fixes.sql` 写入四款镜框：AERO X1、MONOLITH 02、ORBIT T-4、LUCENT V1。`front_end/public/models/frames/` 也只有对应的四个 GLB。线上实际数量以商品接口为准。商品数量、筛选项和 3D 外观是三处独立的数据来源，新增数据库记录后还需逐项对齐。

**首批建议增加四款，令内置目录从 4 款扩至 8 款。** 下表是选品建议，款名、价格、库存和尺寸待按实际样品录入。

| 建议样品 | 视觉差异 | 框型筛选值 |
| --- | --- | --- |
| 香槟金双梁飞行员框 | 水滴形镜片、金属双鼻梁 | `AVIATOR` |
| 酒红猫眼框 | 外眼角上扬、较厚上缘 | `CAT_EYE` |
| 枪灰六角细框 | 清晰折角、细金属圈 | `GEOMETRIC` |
| 琥珀色窄矩形框 | 扁长镜片、半透明板材 | `RECTANGLE` |

**实施顺序**

1. **先做一款完整样品。** 建议从飞行员框开始。分别准备白底主图、能看清双梁或镜腿的细节图，以及同款 3D 模型。图片置于 `front_end/public/images/`，模型置于 `front_end/public/models/frames/`。录入资源路径时使用 `/images/文件名` 和 `/models/frames/文件名.glb`。
2. **录入商品与可售组合。** 单个环境可通过管理后台“镜框产品线”录入中英文名称、材质、基础价、主图、细节图、框型和三段尺寸（镜片宽－鼻梁宽－镜腿长，毫米）。在 SKU 库存维护中建立对应配色和尺寸，实际可售数量按盘点结果录入。如果要让每次新建环境都自带这些样品，可在 `backend/src/main/resources/db/migration/` 新增下一版 Flyway 迁移；当前目录最高为 V26，可用 `V27__expand_frame_catalog.sql`。根据商品关联 `product_ar_configs` 与 `product_skus`，使同一配色的 `finish_id` 及对应尺寸一致。旧版 V24 的 SKU 回填早于这批新品，新增数据时须处理新品自己的 SKU。
3. **接入真实外观。** 在每款的 AR 配置中填写对应的 `model_url`、颜色、模型单位和变换偏移，或按项目惯例在 `front_end/src/ar/frameCatalog.ts` 映射内置资产。这个文件对未知款名会回退到 AERO X1 的样式。若希望模型加载中或加载失败时也显示同款轮廓，就在 `types.ts`、`glassesGeometry.ts` 和款名映射里补上相应轮廓。选用独立 GLB 时检查镜片中心、左右方向与模型比例，尤其是商品尺寸切换到人脸试戴后的效果。
4. **补齐筛选和翻译。** `AdminDashboard.tsx` 和 `ProductDetailsPage.tsx` 已识别 `AVIATOR`，而 `CollectionsPage.tsx` 的下拉框和标签映射仅有圆形、方形、矩形。先把飞行员框加入系列页的两处，再将 `CAT_EYE`、`GEOMETRIC` 同步补到后台录入、系列筛选、详情标签和中英文词条。若使用了新的材质筛选值，也同步维护系列页材质选项。

**验收。** 若测试库仅含原始四款，新增后 `GET /api/v1/products` 应返回八款；已有自建商品的环境按新增四个独立商品核对。对每款执行“按框型筛选 → 打开详情 → 核对图片、配色和尺寸 → 旋转 3D 模型”。对有库存的测试 SKU 再加入购物车，核对商品、配色、尺寸和价格。最后切换中英文，确认新框型在列表与详情中显示一致。


```powershell
Push-Location backend
mvn test "-Dtest=PaymentServiceImplTest,ProductAndLensControllerIntegrationTests" "-Dspring.profiles.active=test"

```
